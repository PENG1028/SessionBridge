# Access Model — 访问模式

## 核心规则

SessionBridge 有三个独立概念，彼此不应互相推断。

| 概念 | 含义 | 判断依据 |
|------|------|---------|
| 节点进程 | 本地 SessionBridge 运行时已启动，可控制本地 adapter/agent | 进程启动 + `/api`/WebSocket 可用性 |
| 中继模式 | 该节点可达性足以接受其他节点作为 relay 接入 | 运行时角色检测或显式配置 |
| 浏览访问 | 浏览器正在查看某个节点页面，但不是该节点进程本身 | 浏览器连接元数据 |

启动节点时必须同时启动本地 UI/API 服务器。中继模式只决定该节点是否对外广播并表现为一个可中继的节点。

## 启动语义

| 状态 | 预期行为 |
|------|---------|
| 节点已启动，支持 relay | 本地页面可用，本地 agent 可控。角色为 `relay`，其他节点可接入 |
| 节点已启动，不支持 relay | 本地页面可用，本地 agent 可控。角色为 `leaf`，可向上游连接 |
| 节点未启动 / 不可达 | 不合成 LOCAL 卡片。UI 显示断开/加载状态，不展示虚假拓扑 |

默认角色检测顺序：

1. 显式 `role=relay` 强制中继模式
2. 显式 `role=leaf` 强制叶子模式
3. 配置了上游 relay 则为 leaf
4. 自动模式使用环境检测：有公网可达则为 relay，否则 leaf

## 实体类型

| 实体 | 含义 | 卡片行为 |
|------|------|---------|
| LOCAL | 提供/拥有此页面的节点进程 | 可点击，可进入/控制该节点。来自服务端 `__local__`，非前端猜测 |
| RELAY | 启用了中继模式的节点 | 可点击的节点卡片，通常显示为网络枢纽 |
| LEAF | 未启用中继模式的节点，通常通过上游 relay 连接 | 可点击的节点卡片 |
| VIEW | 浏览器/客户端进入某节点页面的访问路径 | 灰色信息卡片，不可操控 |

## 拓扑规则

UI 应基于后端上报的节点事实渲染拓扑：

1. 只有本地节点运行时，展示一张 LOCAL 卡片
2. 本地节点连接到其他节点时，展示两张节点卡片及连线
3. 浏览器通过 LAN 节点接入时，展示 VIEW 卡片并连接到该 LAN 节点
4. 浏览器通过 VPS/relay 节点接入时，展示 VIEW 卡片并连接到该 VPS/relay 节点
5. 不根据 `wsUrl`、`upstreamUrl` 或已保存连接伪造 relay/leaf 卡片

## 场景示例

| 场景 | 卡片 |
|------|------|
| 本地 PC 启动 SessionBridge，无公网 | 仅 LOCAL PC（`LEAF`） |
| 本地 PC 启动 SessionBridge 并连到 VPS | LOCAL PC（`LEAF`）→ VPS（`RELAY`） |
| 浏览器直接打开 VPS 页面 | VPS（`RELAY`）+ 该浏览器的 VIEW 卡片 |
| 浏览器直接打开 LAN PC 页面 | LAN PC（`LEAF` 或 `RELAY`）+ 该浏览器的 VIEW 卡片 |
| 程序未实际连接 | 不伪造 LOCAL/RELAY 卡片，显示断开状态 |

## 设置期望

中继模式应可配置，但该设置只控制中继能力，不决定本地页面是否存在。

| 设置 | 含义 |
|------|------|
| 中继模式开启 | 环境支持时尝试成为 relay |
| 中继模式关闭 | 即使环境可能支持 relay 也保持 leaf |
| 环境检查 | 解释为何可/不可启用 relay，如无公网 IP 或可达性检测失败 |

## 当前实现状况

上述模型仅部分实现。

已完成：

1. `NodeRuntime` 无论 relay/leaf 角色都启动本地 HTTP/UI 服务器
2. 自动角色检测不再将"能绑定端口"视为 relay 的充分条件，需要公网 IP 启发式
3. 后端上报真实的 `__local__` 节点用于拓扑
4. 前端不再需要仅靠 `wsUrl` 合成 LOCAL 卡片

仍未完成：

1. 拓扑 UI 仍主要是卡片/树形列表，非真正的图结构，无显式关系连线
2. VIEW 卡片已显示，但其与入口节点的视觉连接未完全呈现
3. 中继模式设置和环境诊断未完全接入设置 UI
4. LAN 暴露的 leaf 访问需要清晰的外部访问策略，避免混淆"仅本地 leaf"和"LAN 可见 leaf"
